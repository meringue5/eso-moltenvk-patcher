# Experiment 0058: ESO 12.1.6 analysis and update-profile design

- Date: 2026-10-24
- Outcome: **succeeded in read-only static analysis and design; no installation or runtime acceptance**
- Rollback: **not required; installed files and selected target preserved**

## Question

Can the new client be handled by deriving compatible patch locations while
preserving its update, and what prevents safe automatic reinstall today?

## Hypothesis

The bridge-facing embedded runtime remains compatible, but its patch locations
may move independently of the host pacing branch. Falsified by changed archive
members, patch signatures, external-reference semantics, proc-query shapes, or
the pacing control-flow proof.

## Target and scope

- Read-only source-auditor mode; no rebase selection, bridge build, install,

  `aef00b13bcc808adf15b85bef9ae67393d92be7ed5dfe41cad16fa809e4a4c5f`.
- Analysis environment: macOS/Apple Silicon; Apple clang 21.0.0

- Previous target and recovery context: Experiments [0054](0054-eso-12.1.5-relinked-update-rebase.md),

## Procedure

1. Check Git, read current operating documents, run `check-update.sh` before
   interpreting evidence, and inspect `status.sh` without launching any app.
2. Invoke `tools/eso_update.py audit` directly against the selected 12.1.5
   reference, current executable/archive/build stamp, and pinned replacement
   runtime. Write the candidate only into temporary analysis storage.
   Do not use `rebase-update.sh`, which also selects the candidate.
3. Inventory installed executable/loader/companions, recovery files, settings,
   caches, production log, and the selected-target pointer for preservation.
4. Compare derived locations and semantic structures. Inspect Bink imports and
   the stored original's exports without treating that backup as a new vendor
   original. Repeat the full source audit to check reproducibility.
5. Inspect native auditor, generated runtime targets, installer transaction,
   and Bink re-export build path. Write the bounded design and next gates.

The clean-original baseline was not available: `status.sh` confirmed an active
bridge. Bundle-idle/install gates were not exercised because this run made no
bundle mutation. No build probe or gameplay request was needed.

## Interpretation

Confirmed: the audited embedded-runtime boundary matches the source reference,
with different independent Vulkan and host-pacing relocations. The installed
attestation is stale and prevents redirection. The game executable remains
unchanged on disk by this work.

Inference: the proposed shared native resolver and per-installation profile
could cover this executable change without a bridge rebuild once implemented.
The current fixed-location package cannot do so. Static equivalence is not
proof of rendering, focus, FPS, or general engine-behavior equivalence.

Unresolved: the current vendor's original Bink is hidden by the retained bridge.
The existing backup cannot resolve that provenance question. Repair must be
performed by the user before any future install can observe the current
original; this run neither performs nor requests that action.
